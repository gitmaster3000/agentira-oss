1. Goals & scope

  • Real endpoints, no mocks. Every request hits a live backend (/api/…) or MCP server, selected purely by environment variables.
  • Full CRUD for all entities: profiles, service accounts, projects, tasks, epics, attachments, notifications, repos, deploy-settings, workflow/RBAC, and the Forge trio — runtimes, agents, runs.
  • Full agent lifecycle: register a runtime → create an agent bound to it → talk to the agent (messages/chat) → assign a task → dispatch a run → simulate daemon progress → complete → verify events, costs, cleanup.
  • Advanced operations: run pause/resume/retry/cancel, conductor tick, gate-checked task moves, scheduler refresh, cost estimation, model catalog, auth-failure matrix.
  • Runnable three ways: Bruno GUI (exploratory QA), bru run CLI (local), CI against the docker-compose.qa.yml stack.

Out of scope: browser/frontend E2E, load testing, the OpenClaw engine suite (already covered in rest/10-openclaw-engine/), and GitHub-webhook HMAC simulation (separate task AP-? candidate).

One .bru file per target under bruno/environments/: local.bru, qa.bru, ci.bru, plus a documented example.bru template. Secrets never committed — supplied via Bruno's --env-var CLI overrides or a git-ignored .env (Bruno reads {{process.env.X}}).

Design rule: requests reference only variables — no literal host, credential, or entity name anywhere in a .bru file. Switching target = switching environment file. That is the whole "maximum variability" requirement.

Runtime-captured variables (set via vars:post-response, prefixed by domain for explainability): auth_jwt, sa_apiKey, proj_id, task_id, epic_id, rt_daemonId, rt_runtimeId, ag_agentId, run_id, run_traceId, att_id, notif_id.

5. Test-daemon strategy

The daemon (agentira-cli/agentira_cli/daemon/core.py) registers runtimes, holds the WS /api/forge/daemon/ws channel, executes runs, and reports completion. Two modes, selected by {{daemonMode}}:

Mode A — simulated (default; pure Bruno, zero external processes)

Bruno itself plays the daemon using {{daemonKey}} (admin bearer):

  1. POST /api/forge/runtimes/register with a synthetic daemon_id = {{runPrefix}}-daemon, provider claude, fake binary path/version → capture rt_runtimeId.
  2. POST /api/forge/runtimes/heartbeat keeps it ONLINE for the duration.
  3. Create agent on that runtime; assign task; POST /api/forge/tasks/{task_id}/run then POST /runs/{run_id}/dispatch.
  4. Since no WS consumer exists, the dispatch lands in the DispatchIntent outbox — assert run status is PENDING/dispatchable rather than RUNNING.
  5. Drive the run manually: POST /runs/{run_id}/start → POST /api/forge/agents/{id}/trigger-events (append streamed events) → POST /api/forge/agents/{id}/trigger-complete → assert terminal COMPLETED, events visible via GET /runs/{run_id}/events.

This exercises every daemon-facing HTTP endpoint and the full run state machine without WS. Known limit: the WS push path itself is untested in this mode.

Mode B — real (nightly / pre-release)

A docker-compose.qa.yml overlay service runs the actual agentira-cli daemon (device-code auth via /api/auth/cli/start|poll|approve — the approve step scripted with the admin JWT). Bruno then only asserts observable state: runtime auto-registered, GET /api/forge/daemon/connections shows the socket, dispatched run reaches RUNNING without manual start. Same specs, different assertions — branch on {{daemonMode}} inside the scripts.

7. Authoring conventions

  • File naming: <order>-<verb>_<object>.bru, e.g. 3-update_agent.bru. One request per file. docs block in every file states purpose + preconditions (Bruno renders it — this is the explainability layer).
  • Auth: collection default bearer {{auth_jwt}}; folder-level override to {{daemonKey}} in daemon-facing folders; explicit auth: none only in 01-auth and negative specs.
  • Assertions: every spec asserts status and at least one body invariant. Cleanup asserts [200,204,404]. Async transitions polled via post-response script loop bounded by {{pollRetries}}/{{pollDelayMs}} — never fixed sleeps.
  • Guards: every dependent spec starts with if (!bru.getVar('proj_id')) bru.runner.skipRequest() so partial folder runs skip instead of exploding.
  • Namespacing: all created names begin {{runPrefix}}-; 99-cleanup sweeps by listing + filtering that prefix, reverse dependency order (runs → agents → runtimes → tasks → epics → projects → service accounts).

Example skeleton:

meta { name: "3-update_agent" }
put { url: {{baseUrl}}/api/forge/agents/{{ag_agentId}} }
docs { Updates model + system_prompt. Requires 11/1-create_agent. Admin JWT. }
script:pre-request { if (!bru.getVar('ag_agentId')) bru.runner.skipRequest(); }
body:json { { "model": "claude-sonnet-5", "system_prompt": "{{runPrefix}} updated" } }
assert {
  res.status: eq 200
  res.body.model: eq claude-sonnet-5
}

8. CI wiring

  1. Workflow spins up docker-compose.qa.yml (project agentira-qa; requires JWT_SECRET, POSTGRES_PASSWORD secrets), waits on 00-health endpoints.
  2. Seed step creates/asserts the admin account (env-provided credentials).
  3. npx @usebruno/cli run bruno/api --env ci --env-var adminPassword=$ADMIN_PW --reporter-junit results.xml; junit uploaded as artifact.
  4. Per-run runPrefix=ci-${GITHUB_RUN_ID} → concurrent pipelines safe on one QA stack.
  5. Nightly job repeats with daemonMode=real and the daemon sidecar service.

9. Risks & open questions

ItemDetail / proposed resolution
Un-gated RBAC mutationsPOST /api/roles, /api/permissions, grant/revoke accept any authenticated user. Phase 7 specs assert 403-for-non-admin and will fail until backend is fixed — recommend filing the backend fix as a sibling task and marking these specs expected-fail until then.
Conductor auto-tick interferenceThe 60s conductor tick may dispatch runs on tasks the suite creates. Mitigation: suite projects use {{runPrefix}} names and agents the conductor doesn't own; if flaky, add a QA-stack env switch to disable auto-tick.
WS endpoints untestable in Bruno/daemon/ws and /ws/runs/{id} have no Bruno primitive. Covered indirectly in daemonMode=real; direct WS tests would need a pytest sidecar — out of scope here.
Reconciler timingStale-run failure (30s reconciler) could race pause/resume specs. Poll budgets in §3 sized above it; keep heartbeats flowing in simulated mode.
Legacy rest/ tree fateProposal: freeze it, migrate its unique coverage (roadmap, openclaw-engine) into api/ during Phase 6, then delete. Needs owner sign-off.
Seed admin credentialsSuite assumes an admin exists (signup is invite-only). QA compose must seed one; credentials flow in via process.env only.
